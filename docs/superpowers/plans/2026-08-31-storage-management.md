# 本地文件存储管理实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 macOS Electron 客户端增加“存储管理”，以回收站、引用保护和孤儿文件扫描解决 `~/.miaos/generated/` 长期增长问题。

**Architecture:** 渲染层负责维护回收站状态和记录恢复所需的业务 payload；主进程新增只允许访问 `generated` 目录的存储服务，负责扫描、校验、统计和逐文件删除。设置页提供完整管理界面，统计查询页只提供占用概览和跳转，项目/历史删除流程统一先写入回收站。

**Tech Stack:** Electron 43、原生 ES Module、Node.js `node:test`、现有 `registerSecureHandler` IPC 封装、现有 `store.js` 状态持久化、现有 settings/history/project 页面和 CSS。

**Spec:** `docs/superpowers/specs/2026-08-31-storage-management-design.md`

## Global Constraints

- 只处理应用自己的 `~/.miaos/generated/` 目录，不触碰用户原始图片或目录外文件。
- 删除节点、项目或历史记录时先进入回收站；只有永久删除或清理孤儿时才物理删除。
- 物理删除必须经过主进程 generated 目录安全校验，拒绝目录穿越、符号链接、目录替换和校验摘要变化。
- 引用计数为零前不得删除文件；文件已不存在视为已清理，单文件失败必须单独报告。
- 第一阶段只修改 macOS Electron 端，不修改 Android，不新增自动定时清理。
- 所有新增注释、文档和用户可见文案使用中文；依赖和脚本继续使用 pnpm。
- 每个任务先写失败测试，再实现最小代码，测试通过后单独提交。

## 完成标准

- 用户能从系统设置看到占用、回收站和孤儿文件。
- 删除项目/节点/历史记录不会立即丢失可恢复状态，也不会留下无法解释的永久删除结果。
- 清空回收站和清理孤儿文件能够释放 generated 目录空间，并报告逐文件结果。
- 共享引用文件不会被误删，目录外文件永远不会被清理。
- 旧版本留下的孤儿文件可以通过首次扫描发现并由用户明确清理。
- `pnpm test` 全绿，`pnpm start` 运行态完成项目、历史、回收站、孤儿扫描和重启验证。
