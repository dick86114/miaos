# 妙生 Electron 项目全面优化设计

## 1. 背景与目标

妙生当前基于 Electron 31、原生 ES Modules 和 CSS 构建，核心生图、项目版本树、历史记录、供应商配置和更新检查功能已经满足现阶段需求。本轮不迁移 Tauri、不引入 React/Vue，也不调整现有页面布局和视觉风格，重点改善可靠性、安全性、可维护性、渲染性能、交互反馈和动画流畅度。

优化完成后应满足：

- 异常退出、数据损坏或版本升级不会静默丢失用户数据。
- API Key、IPC、外部链接、网络请求和更新流程具有明确安全边界。
- 页面切换、项目时间轴、图片列表、弹窗和异步按钮反馈稳定流畅。
- 大型模块被按职责拆分，但现有数据结构和操作路径保持兼容。
- 建立可重复运行的检查、测试、构建和发布验证流程。

## 2. 当前问题基线

当前主要代码规模如下：

- `main.js`：约 1088 行，混合窗口、文件、网络、更新和 IPC 职责。
- `src/js/store.js`：约 928 行，每次变更同步序列化完整状态到 `localStorage`。
- `src/js/pages/project.js`：约 1051 行。
- `src/js/pages/settings.js`：约 1041 行。
- `src/css/pages.css`：约 2883 行，包含较多 `transition: all`。

当前还存在以下约束：

- 应用因 ad-hoc 签名兼容问题关闭硬件加速和渲染沙箱。
- API Key 保存在渲染层存储中。
- 数据目录不可写时会静默回退到临时目录。
- 页面主要通过整块 `innerHTML` 重新渲染并重新绑定事件。
- 暂无自动化测试、Lint、格式化和性能基线。
- CI 使用 npm，而项目统一要求使用 pnpm。
- README 声明 Intel 支持，但当前 CI 仅构建 Apple Silicon。

## 3. 设计原则与范围

1. 采用增量优化，不一次性重写全部代码。
2. 所有状态格式调整必须提供备份、版本迁移和失败回退。
3. 每个阶段同时交付底层改善和用户可感知的体验改善。
4. 动画优先使用 `opacity` 与 `transform`，避免触发布局计算。
5. 异步操作必须具备加载、成功、失败、防重复提交和可恢复状态。
6. 先建立性能基线，再引入虚拟列表、Worker 或复杂缓存。
7. 保持全局串行生图语义，不默认改为并行请求。

明确不做：

- 不迁移 Tauri。
- 不引入新的前端框架。
- 不重新设计页面结构或视觉体系。
- 不改变项目版本树的数据语义。
- 不默认引入远程日志、埋点或用户数据上传。

## 4. P0：安全、数据和发布基础

### 4.1 性能与回归基线

建立包含 200 条历史记录、50 个项目和 100 个版本节点的固定测试数据，记录：

- 冷启动和首屏可交互时间。
- 路由切换和主要页面渲染耗时。
- 时间轴滚动和节点选择期间的主线程长任务。
- 连续切换页面 30 次后的内存、监听器和定时器变化。

同步固化生图、保存图片、项目派生、历史删除、供应商保存、更新检查等冒烟流程。后续改动均使用相同数据和路径对比，核心流程不得明显退化。

### 4.2 数据可靠性

涉及 `main.js` 和 `src/js/store.js`：

- 数据目录不可写时显示阻断性错误，不再静默使用临时目录。
- 状态增加明确 schema 版本、合法性校验和最近一次可用备份。
- 迁移前保留旧状态；迁移失败时不得覆盖原数据。
- 高频修改使用批量或防抖保存，关键操作仍立即落盘。
- API Key 使用 Electron `safeStorage` 加密后由主进程管理。
- 渲染层仅持有调用所需的临时凭据，不输出到日志或页面状态。

### 4.3 Electron 与 IPC 安全

涉及 `main.js`、`preload.js` 和 `src/index.html`：

- 为所有 IPC 参数增加类型、长度、协议、路径和枚举校验。
- 校验 IPC 来源窗口，拒绝未知 WebContents 调用。
- 外部链接仅允许 `https:` 及明确允许的目标。
- 更新日志改用安全 DOM 构造或白名单净化，不直接插入不受信任 HTML。
- 逐步收紧 CSP，移除不必要的 `unsafe-inline`。
- 先修复签名、entitlements 和 Helper 进程兼容，再评估移除 `no-sandbox`、启用 `sandbox: true`。
- 硬件加速只在签名构建和目标 macOS 版本上完成稳定性对照后启用。

### 4.4 网络和错误模型

抽取统一 HTTP 客户端，统一：

- 请求超时、重定向上限、响应体大小和协议校验。
- 网络失败、401/403、429、服务端错误、解析失败和用户取消的错误类型。
- API Key、完整 Base64、敏感路径和敏感提示词的日志脱敏。
- 异步按钮请求锁和重复提交保护。

暂时保持供应商请求串行执行，不改变限流行为。

### 4.5 工程和发布一致性

- 生成并提交 `pnpm-lock.yaml`，移除 npm 安装流程。
- CI 使用 `pnpm install --frozen-lockfile`。
- CI 固定执行检查、测试、构建和产物验证。
- 校验应用版本、Git Tag、Release 名称、DMG、ZIP 和更新清单一致。
- 明确产品只支持 Apple Silicon，或补充 x64/universal 构建；文档与产物必须一致。
- 正式签名与公证作为独立发布增强项，不阻塞其余优化。

## 5. P1：架构、性能与主要交互

### 5.1 主进程拆分

保留 `main.js` 为启动入口，目标结构：

```text
src/main/
├── window.js
├── ipc/
│   ├── files.js
│   ├── providers.js
│   ├── generation.js
│   └── updater.js
├── services/
│   ├── http-client.js
│   ├── image-storage.js
│   └── state-storage.js
└── security/
    ├── validators.js
    └── external-links.js
```

IPC 模块只负责参数校验和服务调用；网络、文件和状态操作不得继续堆叠在 IPC handler 中。

### 5.2 状态层拆分

将 `store.js` 拆分为供应商、项目、历史、设置、持久化和迁移模块。增加细粒度订阅机制，使页面只更新受影响区域。状态 API 保持现有调用语义，先建立兼容入口，再逐页迁移调用方。

### 5.3 页面生命周期

路由和页面统一支持 `mount()`、`unmount()`：

- 离开页面时清理事件、定时器、Observer 和未完成请求。
- 使用 `AbortController` 取消不再需要的请求。
- 列表进入详情后返回时恢复合理滚动位置。
- 页面渲染失败时显示可恢复错误状态，而不是空白页面。

### 5.4 任务队列

保持全局串行执行，同时增加：

- 失败任务原参数重试。
- 等待中任务取消，运行中任务在网络层支持时中止。
- 应用关闭前存在活动任务时提示。
- 队列通知批量合并，避免重复渲染。
- 已结束任务保留上限，防止内存持续增长。

### 5.5 DOM 与时间轴性能

- 小状态变化采用定点 DOM 更新，不整页替换 `innerHTML`。
- 列表使用 `DocumentFragment` 和事件委托。
- 时间轴集中 DOM 读写，并通过 `requestAnimationFrame` 更新位置。
- ResizeObserver、滚动、窗口尺寸变化和输入事件统一节流。
- 大数据量达到实测阈值后再启用分批渲染。
- 图标只对新增区域渲染，避免整页重复生成 SVG。

### 5.6 图片加载

- 列表图片使用懒加载和异步解码。
- 固定宽高比，避免加载后布局跳动。
- 列表优先使用缩略图，详情页加载原图。
- 正确释放 Object URL，避免长期保存大体积 Base64。
- 图片加载失败显示占位、重试和打开文件位置入口。

## 6. 交互动画与反馈规范

### 6.1 动画变量

统一定义快速、常规和慢速动画，建议范围分别为 120ms、180ms、240ms。移除 `transition: all`，明确动画属性。增加 `prefers-reduced-motion`，系统要求减少动态效果时关闭非必要动画。

### 6.2 页面和列表

- 页面切换只使用轻微透明度和 4–6px 位移。
- 页面首次进入播放动画，普通数据刷新不重复播放。
- 新生成图片只对新增元素淡入并轻微缩放。
- 时间轴只动画新增或选中的节点，不重播全部节点。
- 删除元素完成退出动画后再移除 DOM。
- 返回列表时恢复滚动位置，避免视觉跳动。

### 6.3 按钮和异步操作

- Hover、按下、键盘焦点、禁用和加载状态一致。
- Loading 状态保持按钮尺寸不变。
- 异步操作点击后下一帧内给出反馈并阻止重复提交。
- 生图、提示词优化、模型获取和连接测试显示对应阶段。
- 失败提示保留足够时间并提供重试入口。

### 6.4 弹窗、Toast 与空状态

- 弹窗退出动画完成后再删除节点。
- 支持 Escape、焦点锁定和关闭后的焦点恢复。
- Toast 支持去重、堆叠、手动关闭和 `aria-live`。
- 使用应用内确认弹窗替换原生 `confirm`，保持现有确认语义。
- 列表加载使用骨架占位；空状态只优化反馈和动作入口，不改变布局。

## 7. P2：长期质量

### 7.1 自动化测试

- 单元测试覆盖状态迁移、输入校验、错误映射和任务队列。
- Electron 端到端测试覆盖启动、路由、设置保存、项目创建和历史操作。
- Mock Server 覆盖超时、401、429、500 和异常响应。
- 核心服务覆盖率目标为 70%，不设置无意义的全局高覆盖率要求。

### 7.2 代码和样式质量

- 配置 ESLint 和 Prettier。
- 禁止未处理 Promise、重复 IPC 名称和未经净化的不受信任 HTML。
- 将 `pages.css` 按页面拆分，保留统一主题和动画变量。
- 清理重复样式和失效选择器。
- `ui/program*` 历史原型确认用途后归档，不直接删除。

### 7.3 本地可观测性

- 增加本地结构化日志和大小轮转。
- 自动脱敏密钥、Base64 和敏感路径。
- 提供版本、系统、架构、配置状态和最近错误等本地诊断信息。
- 默认不上传遥测或用户内容。

### 7.4 无障碍和键盘

- 补充按钮名称、表单标签和状态说明。
- 核心操作支持键盘导航。
- 保持清晰焦点样式。
- 检查文字对比度、禁用状态和错误提示可读性。

## 8. 验收标准

### 功能兼容

- 供应商配置、连接测试、模型获取、生图、提示词优化、项目版本树、历史记录、图片保存和更新检查均保持现有行为。
- 旧版本用户数据可以自动迁移，失败时可恢复旧数据。

### 性能与稳定性

- 同一测试数据下，主要页面渲染时间不得比基线退化超过 10%。
- 页面切换和滚动期间不出现由应用代码造成的持续性长任务。
- 连续切换页面 30 次后，监听器、定时器和内存不持续线性增长。
- 动画主要使用合成属性，不因动画造成明显布局抖动。

### 安全与发布

- 明文 API Key 不进入日志、页面状态导出或错误信息。
- 所有 IPC 和外部链接均经过校验。
- CI 使用 pnpm 并能完成检查、测试、构建和产物验证。
- 文档声明的平台架构与实际发布产物一致。

## 9. 实施拆分

本设计范围较大，不作为单个实现计划执行，而拆成四个独立、可发布的实施计划：

1. **基础与安全计划**：基线、数据可靠性、密钥、IPC、网络和发布一致性。
2. **架构治理计划**：主进程、状态层、页面生命周期和任务队列拆分。
3. **性能与交互计划**：DOM、时间轴、图片加载、动画、Toast 和弹窗。
4. **质量体系计划**：自动化测试、Lint、日志、无障碍和文档清理。

每个计划都必须保留独立验证、回滚边界和用户可感知成果。执行顺序固定为 1 → 2 → 3 → 4；后续计划不得绕过前一计划建立的安全和测试基础。
