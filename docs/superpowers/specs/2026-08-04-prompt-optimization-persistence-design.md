# 提示词优化状态与碎片重组动效设计

## 目标

改善快速生图与项目生图的提示词优化体验：模型名称在可用空间内尽量完整展示；优化请求跨 Hash 路由持续运行并在返回页面后恢复交互状态；以“文字碎片散开并重组”的输入框内动效替代现有粒子能量场。

## 模型选择控件

`model-chip` 作为工具栏中优先扩展的控件，使用剩余宽度显示模型名称；比例、质量与数量等短控件保持紧凑。宽屏下不设置固定的 140px 文本上限。窄屏时模型名可单行省略，但控件必须保留完整名称的原生提示，并且不得挤压生成按钮、造成中文换行或工具栏溢出。快速生图和项目工作台使用同一响应式规则。

## 运行期优化状态

新增共享优化状态模块，仅在 Electron 当前运行期保存在内存中，不写入 `localStorage` 或项目数据。

- 快速生图使用固定上下文键 `quick`；
- 项目生图使用 `projectId + versionId` 组合上下文键；
- 每个上下文维护 `idle`、`optimizing`、`succeeded`、`failed` 状态，及原提示词、开始时间、结果文本或错误信息；
- 页面挂载时订阅对应上下文；若状态为 `optimizing`，立即恢复只读输入框、按钮加载态和动效；
- 路由卸载只解除页面订阅，不取消实际优化请求；
- 请求结束时更新共享状态。当前页面仍挂载时立即写回结果/提示失败；切换期间结束时，在下一次挂载相同上下文后应用结果或失败反馈；
- 新请求仅允许在非优化状态下启动，避免同一上下文并发写回。

应用重启后状态自然回到 `idle`，不显示遗留优化任务。

## 碎片重组动效

优化期间，真实 `textarea` 保持原提示词但设为只读、低透明度。其上方渲染非交互、`aria-hidden` 的文字碎片覆盖层：按字符或短词切分，长提示词限制为有限片段数量，避免大量 DOM 节点。

碎片动画使用两个循环阶段：

1. 从原文字位置轻微错位、旋转和淡化，呈现“碎裂”；
2. 回到原位置和不透明度，呈现“重组”；
3. 在请求仍未完成时，以不同的延迟重复碎裂与重组；
4. 返回优化结果后，完成一次归位并淡出覆盖层，再将结果写入 `textarea`。

CSS 动画仅使用 `transform` 与 `opacity`，覆盖层裁剪在输入框内并设置 `pointer-events: none`，不得遮挡参考图、按钮或输入交互。用户启用 `prefers-reduced-motion: reduce` 时，不生成碎片运动，仅显示静态处理中状态与轻微高亮。

## 错误处理与清理

无论成功、失败、路由切换或重新挂载，输入框均恢复为可编辑，加载类、`aria-busy` 和覆盖层必须按状态准确清理。失败信息沿用当前中文反馈组件，不暴露供应商密钥或请求头。页面 cleanup 不得清除共享优化任务。

## 测试与验收

新增或扩展自动化测试，覆盖：

- 模型控件在宽屏/窄屏规则下的完整展示、截断降级与提示语义；
- 快速生图和项目生图在优化中切换路由后恢复优化态；
- 任务在离开页面期间成功或失败，返回后正确应用结果或反馈；
- 同一上下文禁止并发优化，结束后完整恢复输入、按钮和 ARIA 状态；
- 碎片层只在优化期间存在、片段数量受限、不可交互，且动画仅修改 `transform`/`opacity`；
- reduced-motion 下无碎片运动；
- 运行 `pnpm check`、`git diff --check`，并在 Electron 手动验证开始优化、切换页面、返回、成功和失败路径。
