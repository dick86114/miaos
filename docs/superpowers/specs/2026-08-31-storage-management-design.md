# 本地文件存储管理设计

## 目标

为 macOS Electron 客户端提供可理解、可恢复、可验证的本地图片生命周期管理，解决删除项目节点后生成图片仍长期占用 `~/.miaos/generated/` 空间，以及历史版本已经删除后无法从状态记录定位文件的问题。

本设计只处理应用生成目录内的文件，不删除用户原始图片、项目目录外文件或用户通过系统文件管理器保存的副本。

## 用户入口

在“系统设置”新增“存储管理”区块，作为完整管理入口。区块包含：

- 当前生成目录占用空间、文件数量和最近扫描时间
- “扫描本地文件”操作
- “打开回收站”操作
- “清理孤儿文件”操作

“统计查询”页面增加轻量存储概览和“管理本地文件”跳转，但不直接承担删除操作。项目删除确认弹窗明确提示：内容会先进入回收站，图片文件暂不立即物理删除。

## 删除语义

### 回收站

删除项目、版本节点或历史记录时，先将对应状态记录移动到回收站，不立即删除文件。回收站条目保留原始记录、删除来源、删除时间和关联文件快照，支持恢复。

删除版本节点时，整个后代子树作为一个回收站条目处理，确保恢复后父子关系和当前版本选择可以还原。删除项目时，项目及其全部版本作为一个条目处理。

### 永久删除

回收站支持单条永久删除和清空回收站。永久删除前展示将删除的文件数量和总大小，并要求二次确认。删除完成后重新扫描并更新结果；单个文件删除失败时保留失败项并报告原因，不把整批操作误报为成功。

### 引用计数

同一文件可能同时被多个活动记录、回收站条目或版本参考图引用。永久删除前建立应用内引用索引：

- 生成结果引用：项目版本图片、快速历史记录
- 参考图引用：版本 `sourceImage`
- 回收站引用：回收站条目中的原始记录

只有引用计数为零的文件才允许物理删除。这样可以避免删除仍被其他节点使用的参考图或图片。

## 孤儿文件扫描

扫描范围固定为应用自己的 `generated` 目录，并将文件分为三类：

1. **使用中**：当前项目、历史或活动任务仍引用。
2. **回收站保留**：已删除记录仍可恢复，因此暂不删除。
3. **孤儿文件**：没有任何活动或回收站记录引用，通常来自旧版本删除逻辑、失败中断或历史迁移。

孤儿列表显示文件名、类型、大小、创建/修改时间和来源状态（可识别时）。支持单选、多选和“全部清理”。对无法读取、非普通文件或符号链接的条目只显示异常状态，不执行删除。

## 数据结构

在现有状态版本基础上增加存储管理字段，不改变已有项目和历史记录契约：

```js
storage: {
  trash: [
    {
      id,
      kind: 'project' | 'version' | 'history',
      deletedAt,
      payload,
      fileRefs: [{ path, size, checksum }]
    }
  ],
  lastScanAt: 0
}
```

`payload` 保存恢复所需的最小原始结构；`fileRefs` 只保存应用生成目录内文件的规范路径、删除前大小和校验摘要，不保存外部用户文件内容。状态迁移时缺少 `storage` 使用空回收站初始化。

## 文件操作边界

- 主进程负责扫描、规范化路径、计算文件大小和执行删除。
- 渲染层只通过受审查的 IPC 获取摘要、预览和执行操作。
- 所有路径必须经过现有 generated 目录安全校验，拒绝目录穿越、符号链接和目录替换。
- 物理删除采用逐文件结果返回，支持应用重启后继续扫描收敛。
- 删除前检查文件是否仍被活动状态引用，避免扫描期间竞态误删。

## 错误与恢复

- 扫描失败：保留上次成功结果，显示本次失败原因和重试入口。
- 文件已不存在：标记为“已清理”，从待删除列表移除，不视为失败。
- 文件被替换或校验摘要不一致：拒绝删除并要求重新扫描。
- 回收站状态保存失败：不执行不可恢复的物理删除，提示状态未完成。
- 恢复时文件已不存在：恢复记录结构，但将缺失图片标记为不可用，允许用户重新生成。

## 迁移与旧数据

历史上已经从项目或历史记录删除的文件没有可恢复的元数据，首次进入存储管理时执行全量扫描，将未被现有状态引用的文件列为孤儿。扫描不会自动删除，必须由用户明确确认。

新版本开始，所有选择或粘贴的参考图都位于 generated 目录并纳入引用索引；删除节点后先保留在回收站，清空回收站或手动清理孤儿文件时才释放空间。

## 验证范围

- 状态迁移能初始化并保留 `storage` 字段。
- 删除项目、主线、分支和历史记录会产生正确回收站条目。
- 恢复能还原原始结构和当前版本选择。
- 引用计数阻止仍在使用的图片被删除。
- 扫描能识别活动文件、回收站文件和历史孤儿文件。
- 永久删除成功、部分失败、文件已不存在、文件被替换等路径均有测试。
- IPC 只允许主窗口调用，路径安全边界和删除结果均由主进程验证。
- 手动运行 Electron，覆盖项目删除、历史批量删除、回收站恢复、孤儿清理和重启后状态恢复。

## 实施边界

第一阶段只实现 macOS Electron 端，不修改 Android。第一阶段不增加自动定时清理或按天数自动过期，避免在没有用户确认的情况下删除文件；后续可在存储管理中增加可选的空间预警和自动策略。
